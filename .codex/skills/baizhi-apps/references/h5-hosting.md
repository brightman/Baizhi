# H5 Hosting

H5 packages are static ZIP files only. The platform validates path traversal, symlinks, ZIP size, extracted size, file count, forbidden extensions/secrets, and the required `index.html` or `dist/index.html` entry. Optional `baizhi-app.json` is checked against the App Manifest.

Lifecycle:

1. Package an already-built static directory with `baizhi-apps h5 package`; never run arbitrary build commands.
2. Create a Draft with `baizhi-apps h5 releases create <app_id> --env <name>`.
3. Upload and validate the exact ZIP and release with `baizhi-apps h5 releases upload <app_id> <release_id> --file <package.zip> --env <name>`.
4. Use `baizhi-apps h5 preview <app_id> <release_id> --env <name>` and inspect the server-issued short-lived preview URL.
5. After explicit user confirmation, publish with `baizhi-apps h5 publish <app_id> <release_id> --env <name> --confirm`.
6. Read current/history with `baizhi-apps h5 current` and `baizhi-apps h5 releases list`; run `baizhi-apps h5 rollback <app_id> <release_id> --env <name> --confirm` only after confirmation with the exact release ID.

Production Draft creation and upload require `--confirm`. Publish and rollback require it in all environments. Never infer the release ID from a display name or silently publish the newest Draft. Preview tickets are short-lived and must not be persisted.

Published files are stored under immutable `apps/{app_id}/releases/{version}/` objects. The Hosting Gateway serves `/apps/{app_id}/` and versioned release paths, preserves query parameters, falls back to `index.html` for extensionless SPA routes, and returns 404 for missing asset-like paths. `config.json` is generated by the platform with the Runtime API and Manifest URLs and is `no-store`.
